# WWF Superstars (arcade) → Sega Mega Drive — fan port

A port of the arcade game *WWF Superstars* (Technōs, 1989) to the Mega Drive / Genesis, written from scratch in C with SGDK. The goal is for the port to be noticeably identical to the arcade: same timing, physics, collisions, reactions and poses, checked against MAME and against the arcade code.

Languages: [Español (original)](README.md) · [Português (Brasil)](README_PT_BR.md) · **English**. For the notes, the Spanish original prevails; translations carry the suffix `_PT_BR` or `_ENG`.

## Important: today the code does not build without the resources

The code is complete, but **it needs resources that come from the arcade ROM**. They are not published and will be generated by an **extractor that is still PENDING** ([tools/extractor/README_ENG.md](tools/extractor/README_ENG.md)). Two things are needed:

- 32 files in `res/` (30 `.bin` and 2 `.wav`): sprites, tiles, maps, palettes, animation tracks, crowd, selection, title and sound;
- 4 headers in `src/gen/`: `ropes.h`, `gs69.h`, `hud.h`, `select89_data.h`.

Until the extractor exists:

- **With the real resources** (the project's private backup) the ROM gives exactly the b95 MD5. Checked while preparing this repository, with `src/gen/` and the `#include` lines already changed.
- **With zero-filled resources** (same sizes) and the 4 headers declared with zeros, **it builds without errors** and produces a ROM of the same size, black and with no playable content. It is only useful to check that the code builds.

**Emilio's edits are not published**: the upper corner posts and the WWF logo in the ring background. The extractor will produce the original arcade background, so with it the MD5 will not match b95 in that part.

## Building (summary; step by step in [docs/ENG/COMPILAR_ENG.md](docs/ENG/COMPILAR_ENG.md))

1. Install **SGDK 2.11**, **m68k-elf-gcc 13.1.0** (with binutils), **Java 17** (for `rescomp`) and `make`.
2. Generate `res/**` and `src/gen/*.h` from your `wwfsstar` set (extractor PENDING).
3. `make GDK=/path/to/SGDK` → `out/rom.bin`. **Do not use `make -B`**: the SGDK template can overwrite `main.c`.
4. Test in MAME 0.276 (`genesis` = NTSC, `megadriv` = PAL) or on real hardware.

## Working method

Summary; the full rules are in [docs/ENG/REGLAS_ENG.md](docs/ENG/REGLAS_ENG.md).

1. **Decompiled code first.** Find the arcade routine and tables, with their address (`docs/analisis/rutinas.md`, `tablas.md`, `ram.md`). Never invent numbers: every value is traced to an address or a measurement.
2. **Then MAME.** Measure the arcade (`wwfsstar`) and the port (`genesis`/`megadriv`) with Lua scripts: positions, ticks, poses, RAM. The arcade moves actor logic every 2 refreshes (57.44 Hz → 28.72 Hz tick); the MD uses `arcTick`. Do not confuse ticks with 60/50 Hz frames.
3. **Noticeable equality.** When a technique is closed it must match the arcade in input, real pace, collision, physics, reaction, poses and palette. Nothing that has not been measured is reported as verified.
4. **Arcade bugs are reproduced** (e.g. the high-byte comparison at `9CD0`); **no new bugs are invented**.
5. **Only what is asked.** Each version goes in a new folder, the base stays untouched, and the new ROM and its MD5 are recorded. Studies do not authorise changes.
6. **Respect what exists:** the SGDK engine (ring, ropes drawn on planes, priorities), Hogan as the reference, palettes, corner posts and logo. No new AI.
